# #65 Feature cache

Set out to: run the frozen model over every frame once and keep the outputs, so experiments read features instead of recomputing them.
Found: the model takes about 121 ms per image, but decoding a 4K RGB frame took another 57 ms; moving decode and patchify to three threads gave 6 to 7.6 images a second. One camera is about 12.5 minutes per half on mains. Final cache: 29,676 files, 11 GB.
Mistake caught in review: 2×2 pooling floored odd grids, so the 35th patch column of every thermal frame (the rightmost 18 px, about one person wide) was dropped, and the index did not record enough to map a cell back to pixels. Fixed with ceil pooling over real patches only and per-entry geometry; `cell_boxes` is the one mapping. The first resume check (2% of the largest value) was about the size of a typical feature value, so it could not have caught a preprocessing change; same-device repeats are exactly equal.
Decision: one file per image (a crash loses one image); hub revision and a preprocessing version in the cache identity; the cache is the one place outside a run directory an experiment writes.
Worth telling: the review came before the 50-minute build, not after. The flaw would have shown up only as slightly worse thermal results.
Sources: PR #76 and its review comment; docs/forward-pass-cost.md.
