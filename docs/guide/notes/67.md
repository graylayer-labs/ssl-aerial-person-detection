# #67 A supervised baseline

Set out to: compare the frozen-feature head with the ordinary approach, an off-the-shelf detector fine-tuned on exactly the same labelled frames, scored the same way, on every fold, camera and fraction.
Chose: torchvision Faster R-CNN with COCO weights. The fair row resizes images to the head's input size; full resolution is a second row, because a detector at native resolution would win on resolution alone. MobileNetV3 over ResNet-50 to fit the laptop (ResNet-50 put the grid at about 8 h per resolution). CPU, because MPS hung or diverged to a loss of 7e7.
Expected before running: the detector to win at 100% and the frozen head to win at 1%, where pretrained features should matter most.
Surprising:
- The opposite at low labels: the detector won all six cells from 1% to 10%, and doubled the head in thermal at 10% (0.256 against 0.129). At 100% they were level.
- It won with a coarser feature map than the head's grid (32 px stride against 16 px cells), so fine-tuning, not detail, is the difference.
- One full-resolution run on the 4K site-day scored 0.779 against 0.213 at the cache size. Resolution is the biggest lever found so far.
- Review caught a silent bug before any run: the anchors gave 3 per location while the pretrained proposal head predicts 15, so the loss indexed the wrong outputs and about 80% of them were never trained. Tests passed throughout; only building the model and comparing shapes showed it.
- The agent's first branch was cut before #68 merged; its diff against main showed 2,234 phantom deletions until it was rebased.
Sources: docs/supervised-baseline-results.md; PR #89 (tooling); issue #67 comments.
